# Learner seed — Samuel

Prefill for onboarding. The learner wrote this; copy it into the profile in their
words. It is self-assessment, not demonstrated understanding.

Language: Deutsch
Implementation style: A mix — learner does the hands-on reps in the focus areas
(see behavior.md, "Hands-on reps"); AI writes the rest.

## Goal
AI Systems Engineer / Forward Deployed Engineer: Agenten bauen können und nicht
von ihnen abhängig sein.

## Known problems
Kann Systeme konzipieren und Agenten dirigieren, steht aber noch nicht sicher
im Maschinenraum. Architektur und Agent Engineering sind gedanklich weiter
entwickelt als die Grundlagen.

## Known gaps
Grundlagen: Python, Git, Debugging, Linux/Shell, Testing.

## Focus (next 8–12 weeks, in order)
Python → Git → Debugging → Linux/Shell → Testing.

## Learning targets (in order)
1. Python wirklich beherrschen — Funktionen, Datenstrukturen, Klassen, Exceptions,
   Files, APIs, Async, Module. Ziel: 300–500 Zeilen fremden Python-Code lesen und
   sinnvoll verändern.
2. Debugging — Stacktraces lesen, Fehler eingrenzen, Hypothesen bilden, Logs setzen,
   reproduzierbare Minimalfälle bauen.
3. Git und GitHub — clone, status, diff, add, commit, branch, merge, rebase, pull,
   push, PRs. Ziel: jederzeit verstehen, was sich geändert hat und warum.
4. Softwarearchitektur und Systemdesign — Komponenten, Interfaces, Datenflüsse,
   Zustände, Fehlerfälle, Queues, APIs, Datenbanken, Auth, Deployment.
5. Linux, Shell und Prozesse — Filesystem, Permissions, Env Vars, SSH, Prozesse,
   Ports, curl, grep, Pipes, Logs.
6. HTTP, APIs und Netzwerke — Request/Response, REST, JSON, Headers, Statuscodes,
   Webhooks, OAuth, DNS, TLS, TCP-Grundlagen.
7. Datenbanken und Datenmodellierung — SQL, Keys, Joins, Indizes, Transaktionen;
   wann Files, SQLite, Postgres, Vector DB oder Object Storage.
8. Testing und Evaluation — Unit, Integration, E2E, Fixtures; für Agenten: Evals,
   LLM-as-Judge, Golden Sets, Regression Tests, Fehlertaxonomien.
9. LLM-/Agentensysteme technisch verstehen — Context Window, Tool Calling, MCP,
   Memory, RAG, Embeddings, Sampling, Agent Loops, Harnesses, Permissions,
   Observability, Evals; wo die Failure Modes liegen.
10. Requirements Engineering und technische Kommunikation — Inputs, Outputs,
    Constraints, Edge Cases, Acceptance Criteria.

## Yardstick
Nicht „habe ich das Tutorial verstanden?“, sondern: Kann ich ohne Agent einen
kleinen Fehler finden, den Code ändern, testen, committen und erklären?
